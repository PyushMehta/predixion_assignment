**Baseline answer** (single LLM call, no tools; high, 1.9s): Several strategies exist for giving an AI support agent a memory that can be used to improve continuity, personalization, and problem‑solving:

1. **Short‑term (session) context** – The agent stores the last few user‑assistant turns in a sliding window and prepends them to each new prompt. This is simple, works with any LLM, and keeps the model aware of the immediate conversation, but it forgets older details once the window exceeds token limits.

2. **External knowledge base (KB) lookup** – Relevant facts (e.g., user profile, ticket history) are saved in a structured store (SQL, NoSQL, vector DB). When a new query arrives, the system retrieves matching records and injects them into the prompt. This provides persistent, searchable memory and scales across many users, but requires engineering of retrieval logic and may introduce latency.

3. **Vector‑based semantic memory** – Past interactions are embedded and stored in a vector index. Similarity search returns the most relevant prior dialogues, which are then summarized or directly included. This captures nuanced context beyond exact keyword matches, yet needs periodic pruning and careful summarisation to stay within token budgets.

4. **Fine‑tuning or continual learning** – The model is periodically retrained on aggregated conversation logs, effectively baking common patterns into its weights.
