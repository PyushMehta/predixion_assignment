**Baseline answer** (single LLM call, no tools; high, 1.4s): Several strategies exist for giving an AI support agent memory:
1. **Short‑term context window** – keep the last N user‑assistant turns in the prompt. Simple, works with any LLM, but limited by token budget and loses older info.
2. **External knowledge base / vector store** – embed past interactions, store them in a searchable index, and retrieve relevant snippets to prepend to the prompt. Provides scalable, persistent recall and can be filtered by relevance, but adds latency and requires embedding models.
3. **Structured state store** – maintain a JSON or database of key facts (e.g., ticket ID, user preferences, issue status). The agent reads/writes this state via API calls. Guarantees deterministic access to critical data and is easy to audit, though it requires explicit design of what to store.
4. **Hybrid approach** – combine a short‑term window for immediate conversational flow with a vector store for broader historical context and a structured store for essential variables. This balances immediacy, depth, and reliability.
5. **Fine‑tuned or Retrieval‑Augmented Generation (RAG) models** – train the model on past dialogues or use a RAG pipeline that injects retrieved memories directly into the generation process. Offers more seamless integration but needs extra training or infrastructure.
Choosing a method depends on factors such as required persistence, latency tolerance, complexity of the domain, and how much control you need over what the model remembers.
